# Проверка управления ограничениями

## Реализация и источник контракта

Шесть команд `restrictions` зарегистрированы как недокументированное расширение.
Контракт взят из серверных `routes/api.js`, `controllers/space/restrictionsController.js`,
`api/schema/create/restriction.json`, `api/schema/patch/restriction.json` и модели
`Restriction` локального checkout Kaiten; серверные файлы не изменялись.
`get` выбирает UUID из GET коллекции; `copy` использует POST целевой коллекции.

## Утверждения и проверка

| Утверждение / инвариант | Проверка в `tests/test_restrictions.py` |
|---|---|
| Флаги, файл и stdin дают одинаковые запросы | Точные HTTP method/path/query/body для каждой команды; оба имени файлового параметра |
| Частичный PATCH не вставляет defaults и не сливает массивы | Проверки `active`, `disabled`, `null`, пустых строк и массивов; произвольный `data` |
| Структура правил соответствует серверной схеме | Пропущенные поля, неверные типы, операторы и длины отклоняются до HTTP |
| Чтение одного правила не маскирует ошибки | Отсутствие, чужой UUID, malformed collection, workflow/removed правила |
| Ответ копирования сохраняет `broken` | Проверяется полное совпадение ответа |
| Записи защищены общей политикой CLI | Флаг и env read-only для всех четырёх мутаций |
| Неоднозначная мутация не повторяется | Timeout, HTTP 500, malformed success; ровно один запрос |
| Серверные ошибки сохраняются | HTTP 400/401/402/403/404/409 и исходное тело ошибки |

Метаморфные проверки: одинаковый результат разных способов ввода, поиск UUID
независимо от регистра и позиции правила в списке.
Discovery/help проверяются на русском и английском; машинные значения не переводятся.

## Допущения и риски

Серверные ограничения принадлежат пространству. Типоспецифичное содержимое `data`
остаётся непрозрачным для CLI и проверяется сервером. Общий JSON Schema validation
CLI не исполняет `anyOf`, поэтому правило непустого PATCH проверяется отдельным
payload validator. Ограничения workflow доступны через отдельный Workflow API.

Маршруты не опубликованы как гарантия Public API. Live-сценарии написаны, но не
запускались; все шесть команд имеют статус `live_not_validated`.
В диагностике остаются стандартные request counts, execution mode, API errors и trace.

## Приёмка

Локальная приёмка: полный `pytest`, `ruff check`, `ruff format --check`,
`scripts/check_locales.py`, `scripts/generate_reference_docs.py --check` и `git diff --check`.
Результат 2026-10-06: **1417 passed, 3 deselected**; lint, форматирование,
2933 сообщения каталога EN/RU, актуальность документации и diff-check прошли.
При подготовке `v0.3.2` полный прогон с branch coverage также прошёл:
**1417 passed, 3 deselected**, покрытие **84,40%** при пороге 75%.
sdist и wheel собраны; установка wheel в чистое окружение подтвердила версию
`0.3.2`, наличие шести команд и discovery EN/RU без live-вызовов.
Отдельный live-сценарий проверен через `--collect-only`, без запуска fixture и HTTP.
Live lifecycle запускается только с `KAITEN_LIVE=1|true`, затрагивает созданные для
прогона правила и пространства и проверяет cleanup через список правил.

Вердикт: **Safe with conditions** — расширение пригодно для локальной интеграции
после зелёных offline-проверок; совместимость с конкретным live-сервером требует
отдельного opt-in прогона.
