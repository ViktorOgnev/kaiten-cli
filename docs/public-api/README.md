# Проверка паритета публичного API Kaiten

Проверка выполнена 21 сентября 2026 года по [developers.kaiten.ru](https://developers.kaiten.ru/), индексу `llms.txt`, навигации всех разделов и вложенным таблицам Schema автоматизаций. Это проверка документированного контракта и локального выполнения CLI; запросы к production и live-мутации не выполнялись.

## Результат

В снимке **316 страниц**: **222 HTTP-операции** (214 REST и 8 SCIM) и **94 справочные страницы**. Все HTTP-маршруты сопоставлены с CLI и проверяются тестами построения запроса. **198 операций** покрыты без отмеченных расхождений анализируемой схемы; **24** имеют явные пояснения совместимости, противоречия документации или ограничения. Неразобранных страниц и необъяснённых пропусков в снимке нет.

`covered` в машинном отчёте означает покрытие проверенных method/path, query/body-полей, типов, перечислений и известных вложенных структур. Это не утверждение о полной реализации JSON Schema или о live-проверке сервера. Неструктурированные ограничения из текста сохраняются как метаданные; клиентская проверка намеренно допускает расширения сервера.

| Артефакт | Содержание |

| [contracts.json](contracts.json) | Контракты, URL, дата проверки, SHA-256 страниц и исходного JS с таблицами автоматизаций |

В CLI сохранены 417 команд и прежние MCP-алиасы. Расширены параметры существующих команд, а не добавлены дублирующие семейства.

## Что изменено

- Доски: создание с колонками и дорожками, автоперемещение, автоназначение, WIP ячеек, теги, обязательность полей, размещение и параметры отображения.
- Колонки, подколонки и дорожки: предупреждения о простое, автоархивирование, скрытие карточек, правила, позиционирование и пауза SLA.
- Пространства, пользователи и группы: скрытые типы карточек, настройки, уведомления, роли и права. Новые парольные аргументы редактируются в trace.
- Пользовательские поля и справочники: формулы, ограничения значений, вложенные настройки полей с ключами UUID, голосование и параметры каталогов.
- Документы: настройки публикации, доступа, адресов и групп; сохранены существующие преобразования Markdown.
- Дополнены фильтры чтения, параметры удаления, альтернативные формы создания, именованные поля SCIM. Для назначения нового расположения чеклистов используются `target_card_id`, `target_checklist_id`, `target_space_uid`: идентификаторы исходного URL не заменяются.
- Автоматизации: 27 описанных действий, 25 условий и 20 уникальных типов триггеров из модальных таблиц. Проверяются известные структуры, группы `and/or`, типы значений, допустимые сочетания и календарные смещения. `on_demand` не требует триггера; событийный/календарный вариант не требует имени; частичный PATCH не требует остальных атрибутов автоматизации.
- Исправлена передача query-параметров через HTTP-транспорт для POST/PUT/PATCH/DELETE, camelCase-флагов и объединённых типов. Добавлены регрессионные тесты от CLI-ввода до HTTP, включая дробные числа, `null`, строковые/массивные значения и `published_version`.
- `describe` теперь возвращает `input_schema` и выводит вложенные поля в терминале. Сложные параметры одинаково доступны через JSON-флаги, файл и stdin.

## Совместимость и противоречия источников

- Неизвестные вложенные поля и новые строковые варианты автоматизаций передаются без изменения. `on_workflow`, копирование и одиночное чтение автоматизаций сохранены как существующие расширения, без объявления публичного контракта. Отсутствующий `type` не подставляется автоматически.
- Данные `created` у действий и `hasToFireOnCardCreation` у триггеров остаются необязательными для прежних вызовов; модальные таблицы указывают их обязательность, а часть примеров/старых вызовов обходится без них. Исходная обязательность доступна в `x-documentation-required`; рекомендации содержат явные даты действий.
- Календарные таблицы используют `offset_units`, официальный пример — `offset_unit`. Оба написания описаны и передаются буквально. Не выполняется догадочное переименование. Для относительного смещения требуются `offset` и одно из двух написаний единицы.
- Несколько модальных таблиц имеют четыре заголовка и пять ячеек; одна строка содержит лишнюю пустую ячейку. Нормализатор обрабатывает эти конкретные формы, а неизвестную структуру считает ошибкой. `{uuid}` и `{custom_property_id}` трактуются как шаблоны ключей; `customProperty_97` не превращается в обязательный буквальный ключ `{custom_property_id}`.
- `all_conditions_met` и `add_timeline` упоминаются в описании ответа, но отсутствуют в подробных модальных схемах. Они проходят как расширения; их несуществующие подробные схемы не выдумываются.
- `settings` пространства и некоторые другие JSON-объекты не имеют опубликованной полной схемы. Они принимаются как открытые объекты. У доски request использует `columnIds`, а response-таблица содержит `columnsIds`; формат запроса не изменяется по описанию ответа.
- Таблицы пагинации местами говорят `number`. CLI сохраняет целочисленные счётчики и индексы. Устаревший `include_values` не возвращается в запрос после ранее реализованной миграции Public API.
- `months_to_hide_cards` остаётся в схеме портала вместе с объявлением удаления. Используется `card_hide_after_days`; пересчёта месяцев в дни нет.
- Устаревшие multipart-вложения комментариев `files[]` не подменяются JSON-массивом. Используется существующая загрузка restricted-access файлов. JSON-команды чтения метаданных отклоняют `redirect=true` с указанием `files.download`; бинарное скачивание остаётся в специализированном безопасном потоке.
- SCIM содержит таблицы с неназванными вложенными полями и противоречивым типом `emails`. Сохранён свободный `payload`, добавлены именованные поля; `emails` допускает объект и массив. Для PATCH проверяется структура Operations, но новые пути сервера не запрещаются.
- Форматы импорта, callback-данные User Metadata, события External Webhooks и браузерный SDK аддонов учтены в перечне справочных страниц. CLI не получил сервер приёма вебхуков, браузерный SDK или валидатор пакетов импорта.

## Повторение проверки

Офлайн-проверка не обращается в сеть и не требует Node.js:

```bash
.venv/bin/python scripts/audit_public_api.py
.venv/bin/python scripts/generate_reference_docs.py --check
.venv/bin/pytest -q
```

Явное обновление доказательств требует доступа только к порталу документации и Node.js для извлечения клиентских таблиц. Оно не меняет реестр автоматически:

```bash
.venv/bin/python scripts/audit_public_api.py --refresh
# Проверить diff источников и решения по новым расхождениям.
.venv/bin/python scripts/normalize_automation_docs.py
.venv/bin/python scripts/audit_public_api.py --write-report
.venv/bin/python scripts/generate_reference_docs.py --write
```

По умолчанию `--refresh` использует новый временный каталог. `--cache-dir` явно разрешает повторное использование ранее загруженных страниц для отладки. Изменившаяся структура JS завершает извлечение ошибкой; старые схемы не выдаются за успешно обновлённые. SHA таблиц и соответствие нормализованным схемам проверяются офлайн.

## Верификация изменений

**Проверяемые утверждения:** документированные поля доступны пользователю и доходят до правильного места в запросе; известные ошибки автоматизаций обнаруживаются до HTTP; совместимые расширения и существующие маршруты сохраняются.

**Допущения:** документация описывает публичный контракт, но может противоречить сама себе; доступность функций зависит от версии сервера и тарифа. Источники проверяются отдельно от реестра, сетевое обновление не входит в обычные тесты.

**Инварианты:** `false`, `0`, `null` и пустые массивы не теряются; PATCH не добавляет непереданные настройки; источник и назначение переноса различаются; новые поля не обходят read-only guard; trace не раскрывает новые парольные аргументы.

**Тестовые обязательства:** source-backed построение маршрутов всех 222 HTTP-операций, точные query/body для настроек и переносов, варианты автоматизаций, JSON-флаги/файл/stdin/MCP-алиас, синхронность снимков и документации, полный существующий набор тестов, сборка и отдельная установка wheel.

**Граничные сценарии:** пустые действия и более десяти действий, неверные типы во вложенных списках, недопустимые сочетания триггера/действия, пустые условия, ограничение глубины условий, UUID-ключи, числовые enum без смешивания с boolean, неизвестные расширения, частичный PATCH и недоступная страница источника.

**Проверки свойств и регрессий:** JSON round-trip не меняет автоматизацию, валидация не меняет исходные схемы, существующие тесты сравнивают прежние маршруты и преобразования. Количество команд и алиасов сохраняется.

**Риски:** отсутствие live-проверок и противоречия портала, перечисленные выше. Offline coverage не доказывает права доступа, тарифную доступность и фактическое исполнение автоматизаций сервером.

**Наблюдаемость:** ошибки содержат путь проблемного поля; отчёт перечисляет каждую страницу, а не только итоговый процент. Неразобранная HTTP-страница, несопоставленный маршрут, новое необъяснённое расхождение или устаревшие схемы дают ненулевой exit code.

**Результаты проверок:** полный офлайн-набор — 1067 passed, 2 deselected (live); branch coverage 83,67%; Ruff, синхронность сгенерированной документации, офлайн-аудит и `git diff --check` прошли. Собраны wheel и sdist; wheel установлен в отдельное окружение, проверены обе точки входа и вложенные схемы в JSON/текстовом `describe`. Предупреждения pytest относятся к существующему использованию устаревающего `click.get_text_stream`.

**Вердикт:** Safe with conditions — перечисленные локальные проверки пройдены; гарантия live-паритета требует отдельной проверки на разрешённом тестовом сервере. Изменения подготовлены к выпуску 0.3.0: аннотированный тег, атомарный push и GitHub Release публикуются после локальных проверок; публикация Release требует успешного CI. Production и live-мутации в выпуск не входят.
